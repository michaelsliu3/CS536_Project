# Scripts

Run every script from the project root with the project's environment, e.g.
`.venv/bin/python scripts/dataset/build_dataset.py data/aacr`. Each script finds the project
root from its own location, so the working directory only matters for relative arguments.

| Folder | Script | What it does |
|---|---|---|
| `dataset/` | `build_dataset.py` | Builds the context levels for every AACR-Bench PR into `ROOT/context_levels.jsonl` (setup checks, retries, logs, resume). With `--unit hunk` it packs a set of levels for every diff hunk (the per-hunk test), which needs a folder of its own: `data/aacr_hunk`. A folder that holds per-PR records is refused. See `src/tracer_context/README.md`. |
| | `clean_dataset.py` | Deletes a build and downloaded repositories so the next build starts over. |
| | `contextcrbench.py` | Turns ContextCRBench into a dataset folder `build_dataset.py` can read (the pilot, `data/ccrb_hunk`). `threads` reduces the records to one row per comment thread; `lookup` asks GitHub for the commit each comment was made on (ContextCRBench stores the PR's final code, not what the reviewer saw); `write` writes `positive_samples.json` in AACR's shape; `check` compares the built hunks with the code the reviewers saw. |
| `tracer/` | `build_tracer_context.py` | Builds one review context for one PR checkout, with a config. |
| | `run_tracer_batch.py` | Builds per-PR folders (trace, every level's `context.md` and `selection.json`) for inspecting chosen AACR entries. |
| `setup/` | `download_reviewer_model.py` | Downloads the outcome table's reviewer, `Qwen/Qwen3.8-27B` at the revision `notebooks/outcome_table.ipynb` pins (about 55.6 GB), through hf-mirror.com into the Hugging Face cache. It never contacts huggingface.co, which is unreachable from mainland China (a request that would go there stops the run, and the log lists every host contacted); the mirror redirects the large weight files to Hugging Face's file CDN under hf.co, which is reachable there. It verifies every file, and prints the `vllm serve` command for the `cloud` profile. Re-run it to resume: finished files are kept and a partly downloaded weight file continues where it stopped. A connection that stays below 500 KB/s is replaced by a new one (`--min-speed`). `--dry-run` downloads nothing. |
| | `check_device.py` | Checks the PyTorch device (CUDA, MPS or CPU). |
| | `test_qwen.py` | Loads Qwen2.5-Coder-7B for a smoke test (large download). |
| | `llamafactory_ui.sh` | Starts the local LLaMA-Factory web UI (see the root README). |
| `outcome/` | `run_reviews.py` | Runs the outcome table's review stage from a terminal with the notebook's profile (`cloud` by default), so a long run can sit in `screen`. Saves each review as it arrives, resumes on re-run, and logs every call to the run folder's `logs/`. Applies the profile's retry rule to a reply that was cut off or has no JSON, including replies saved by an earlier run (`src/review_outcomes/README.md`). `--first N` reviews only the first N PRs and estimates the rest; `--entries` names PRs; `--dry-run` prints what a run would send without calling the server. |
| | `run_judgments.py` | Runs the outcome table's judge stage from a terminal on the reviews `run_reviews.py` saved, with the profile's judge, then writes `table.csv` and `coverage.csv`. Makes no reviewer call, resumes on re-run, and logs to the run folder's `logs/`. `--dry-run` prints what it would judge without calling the server. |
| | `label_references.py` | Labels reference comments that come without labels (human review comments, as in the ContextCRBench pilot) with the profile's judge model: whether each is a finding at all, and its category, context level and severity. Saves one line per comment and keeps saved labels on re-run. |
| `harness/` | `record_codex.py` | Records what a real coding agent reads before it reviews a hunk, as a comparison level (`HC1_codex`). `check` tests the Codex CLI, its settings and the model server; `run` runs Codex read-only on each hunk's checkout and saves its event stream; `build` writes the commands it ran and their output as a level in `ROOT/context_levels.codex.jsonl`, reviewed with the `cloud-ccrb-hunk-codex` profile. Codex runs with a home folder of its own, never `~/.codex`. |
| `analysis/` | `analyze_predictions.py` | Analyzes saved paired predictions (see `src/evaluation/README.md`). |
| | `preview_context_selection.py` | Previews one context policy with a local tokenizer, without inference. |
| | `compare_selector_llm_runs.py` | Compares the M2 and A100 small-LLM selector runs on common folds: the M2 run's 5 folds (the two runs' scikit-learn versions split the repositories differently) and the first selector run's 20 leave-one-repository-out folds. It re-scores the cached model outputs and writes `results/selector_llm_results_a100/same_folds/` and `loo_folds/`. Needs `SELECTOR_DATA` set to the data folder. See `docs/selector_llm_a100_run.md`. |
